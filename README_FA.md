**یک پنل مرکزی تحت وب، چند Worker نود مستقل، یک هویت اشتراک و یک سهمیهٔ کل/روزانهٔ مشترک؛ بدون وابستگی اجرایی به نهان.**

## دقیقاً دو فایل موردنیاز

| فایل | کاربرد |
|---|---|
| **[manager-worker.js](manager-worker.js)** | یک بار روی Worker مرکزی: پنل وب، حساب‌ها، رجیستری نود، اشتراک/QR و دفتر معتبر سهمیه در D1 |
| **[node-worker.js](node-worker.js)** | روی هر Worker نود: اتصال API و تونل VLESS/Trojan روی TLS WebSocket؛ بدون D1 یا KV نود |

هر کدام **ES module کامل و آمادهٔ paste** است؛ تمام فایل را جایگزین کنید. نصب npm، build، رابط بیرونی یا VPS لازم نیست. نود نهان، master key یا انتخاب ROLE نمی‌خواهد.

این نسخه روی شاخهٔ **`arena/4a2b629b-nexiup`** است. **main عمداً تغییر نکرده**؛ دانلود شاخهٔ پیش‌فرض را معادل این انتشار ندانید. پوشهٔ `mesh/` سورس توسعه است، نه فایل اضافی لازم برای استقرار.

> **`worker.js` فایل مدیر Mesh نیست**؛ نسخهٔ قدیمی/یکپارچهٔ **۲٫۱٫۲** است که ربات، پرداخت، کیف پول، معرفی و کاتالوگ ProxyIP در آن حفظ شده‌اند. **این جریان قدیمی خودکار حساب Mesh صادر نمی‌کند.** [راهنمای جزء قدیمی](docs/LEGACY_FA.md) جداست. Mesh را روی **Worker و origin جدید** نصب و از D1 پشتیبان بگیرید؛ مهاجرت خودکار دادهٔ مالی، هویت یا URL قبلی انجام نمی‌شود. `wrangler.toml` ریشه نیز قدیمی است؛ Mesh دو پیکربندی نام‌دار دارد.

## نصب کوتاه

۱. **مدیر:** Worker جدید، کد کامل `manager-worker.js`، binding نوع D1 با نام **`DB`** و Secret تصادفی ASCII **`OWNER_KEY`** با طول ۳۲ تا ۲۵۶ نویسه.
۲. **هر دو فایل:** compatibility date برابر `2026-10-20` یا جدیدتر و flag **`global_fetch_strictly_public`**. Deploy کنید. `/health` نوع و نسخهٔ کد فعال را می‌گوید، نه آمادگی دیتابیس/شبکه را.
۳. **پنل مرکزی:** `/admin`، ورود با `OWNER_KEY`. ورود اولِ مجاز جدول‌های `nx3_` را آماده می‌کند. در **تنظیمات**، origin واقعی HTTPS مدیر را ذخیره کنید.
۴. **هر نود:** Worker جدا با `node-worker.js`؛ متغیرهای **`NODE_ID`** و **`MANAGER_URL`** برابر origin مدیر، و Secret مستقل **`NODE_KEY`**. **D1، KV و cron روی نود لازم نیست.**
۵. **اتصال:** همان مقدار NODE_KEY را روی مدیر در Secret با نام `NODE_KEY_<NAME>` قرار دهید. در فرم **نودها**، شناسه، HTTPS origin و **نام مرجع راز** را وارد کنید، نه مقدار آن. ذخیره → **تست API** → **فعال‌سازی**. challenge باید واقعاً در مدیر دیده شود؛ HTTP 200 کافی نیست.
۶. **اشتراک:** حجم کل/روزانهٔ مثبت برحسب GiB، مدت/انقضا، سقف پذیرش تونل هم‌زمان، پروتکل و **همهٔ نودهای فعالِ فعلی و آینده** یا نودهای انتخابی را تعیین کنید. یک لینک/QR تحویل دهید؛ ساخت دستی حساب روی هر نود لازم نیست.

راهنمای دقیق همهٔ مراحل، امنیت/API، معنای سهمیه، خطایابی و احتیاط مهاجرت: **[docs/MESH_FA.md](docs/MESH_FA.md)** / **[English](docs/MESH.md)**.

## پنل واقعاً چه کار می‌کند؟

- فارسی/انگلیسی، RTL/LTR و موبایل؛ ورود/نشست/CSRF و خروج امن.
- ثبت/تست دوطرفه/فعال و غیرفعال‌کردن نود؛ clean host اختیاری و حداکثر چهار fallback از ورودی خود مدیر. کشور، ادعای مدیر است نه اثبات محل خروجی.
- ساخت، ویرایش، تمدید، توقف، ادامه، لغو و reset واقعی؛ کنترل نسخه و nonce ماندگار. تمدید، مصرف را پنهانی صفر نمی‌کند.
- همان UUID میان نودها و نسخه‌های اپراتوری؛ یک URL اصلی، PNG واقعی محلی، Xray کامل و raw/base64. قالب ناسازگار صریح رد می‌شود.
- تنظیمات مستقل ایرانسل/همراه اول/استاندارد، اعتبارسنجی و rollback نسخه‌دار؛ بدون ادعای تأیید اپراتور/کلاینت واقعی.
- مصرف گزارش‌شده جدا از رزرو/نامشخص و تفکیک نود؛ روز UTC، audit، بررسی خواندنی دیپلوی و نگهداری محدود اختیاری.

هیچ IP زندهٔ ساختگی، host/UUID/کلید نمونه به‌عنوان تنظیم تولید فعال نشده است. استقرار خودکار کد نیز پیاده‌سازی نشده است.

## محدودیت مشترک، نه چند برابر شدن حجم

اشتراک **۱۰ GiB روی سه نود، همان ۱۰ GiB کل** است. تراکنش مرکزی D1 پیش از ارسال payload، حجم رزرو می‌کند. رفت/برگشت از اعتبار سریال مشترک مصرف می‌شود و قطعهٔ آخر به اندازهٔ باقیمانده بریده می‌شود. نوشتن D1 به‌ازای هر فریم نداریم.

بسته‌شدن معتبر، اعتبار استفاده‌نشده را **یک‌بار** برمی‌گرداند. اگر نود یا پاسخ تخصیص از بین برود، اعتبار نامشخص محافظه‌کارانه در سهمیه می‌ماند و جدا نمایش داده می‌شود؛ نه به‌عنوان مصرف قطعی جعل، نه حدسی آزاد می‌شود. گزارش معمول هنگام پایان اعتبار/بستن اتصال است. header اشتراک رزرو را هم حساب می‌کند تا حجم تخصیص‌یافته کمتر نشان داده نشود.

روزانه در **00:00 UTC** تازه می‌شود. اتصال تازه وضعیت حساب/نود/عضویت/انقضا را بررسی می‌کند؛ مجوز موجود حداکثر **۳۰ ثانیه** عمر و بازبینی ۲۰ثانیه‌ای دارد. Reset و تعویض هویت، مکث تخلیهٔ ۳۱٫۵ثانیه‌ای دارند. هر تونل فعلاً حداکثر **چهار دقیقه** و **۳۶ RPC کنترل** دارد؛ کلاینت باید دوباره وصل شود و انتقال بسیار طولانی بی‌وقفه تضمین نیست. سقف سراسری، **تعداد تونل** است نه اثبات تعداد دستگاه.

نود باید **تحت کنترل و مورد اعتماد شما** باشد؛ نود مخرب می‌تواند شمارندهٔ خودش را دور بزند. قطع مرکز fail-closed است. guard فعلی **۱۲ نود**، صف‌های محدود و پلن مثبتِ متناهی است. **VLESS/Trojan روی TLS WebSocket برای TCP** پشتیبانی می‌شود؛ UDP/Shadowsocks/XHTTP/gRPC جزو این جفت نیستند.

**Free، وعدهٔ ظرفیت نیست.** کد افزونهٔ پولی لازم ندارد، اما پذیرش، رزرو، تسویه و بازبینی مجوز، درخواست/نوشتن D1 واقعی با هزینهٔ trigger/index می‌سازند. CPU، سهمیهٔ مشترک حساب، ذخیره و رفتار کلاینت را پیش از تولید اندازه بگیرید؛ D1 و رازهای Worker را خصوصی پشتیبان‌گیری کنید.

## فایل پیوست و خطای 1101

فایل پیوست بررسی شد، نه اینکه کورکورانه کپی شود. یک **تفاوت سازگاری واقعی** بازتولید شد: از تاریخ **2026-03-17**، باینری WebSocket پیش‌فرض **Blob** است. فایل پیوست `binaryType='arraybuffer'` تنظیم کرده بود؛ NexiUP ۲٫۱٫۱ نمی‌کرد. تست native، **Blob و صفر بایت در تبدیل ساده** را دید و پس از اصلاح، WS/TCP کار کرد. نود Mesh ۳٫۰٫۰ و Worker قدیمی ۲٫۱٫۲ آن را **پیش از `accept()`** تنظیم می‌کنند و تست‌ها پیش‌فرض Blob را مدل می‌کنند.

این، **توضیح همهٔ 1101ها نیست**. نهان ۳٫۰٫۴ بررسی‌شده همین تنظیم را دارد؛ پس علت خرابی دیپلوی نهان با این یافته مشخص نشده است. `request.fetcher` در types/runtime فعلی هست و import استاندارد سوکت هم محلی کار کرد. مدرکی نداریم که کامنت اضافی حدود ۴٫۸ MB فایل پیوست جلوی استثنا را بگیرد. مدیر import سوکت ندارد، نود API مستند را بعد از مجوز می‌گیرد و boot عمومی هیچ‌کدام D1 نمی‌خواند.

اگر `/health` جدید هنوز خطای بستر است، نسخه/route فعال و exception واقعی لازم است. بررسی خواندنی و متغیر اختیاری **`NEXIUP_DIAGNOSTICS="true"`** شناسه/کد امن، حتی برای خطای پس از ارتقای تونل، می‌دهند. رویداد کامل Cloudflare با URL/هدر حساس را منتشر نکنید. استقرار حساب واقعی یا موفقیت اینترنت ایران ادعا نشده است.

## توسعه و آزمون

```sh
npm ci
npm run verify
npm run build:mesh  # فقط پس از ویرایش سورس توسعه یا helperهای متعلق به پروژه

# قبل از هر استقرار واقعی، ID/متغیرها/رازهای خودتان تنظیم شوند:
WRANGLER_SEND_METRICS=false npx wrangler deploy --config wrangler.manager.toml --dry-run
WRANGLER_SEND_METRICS=false npx wrangler deploy --config wrangler.node.toml --dry-run
```

**۱۶۷ تست داخلی موفق‌اند**: ۴۳ مورد تازهٔ Mesh و تمام ۱۲۴ مورد قبلی. تست workerd، **فایل خام و bundle** مدیر/دو نود را با D1 واقعی، challenge مشاهده‌شده و WebSocket/TCP واقعی به **echo محلیِ مشخصاً آزمایشی** بررسی می‌کند. نود اول ۶ بایت و نود دوم دقیقاً ۱۴ بایت دیگر در سقف مشترک ۲۰ بایت پذیرفتند؛ بایت/اتصال TCP بعدی رد شد. مرورگر HTTPS واقعی، ورود/CSRF، ثبت نود، ساخت/انتخاب حساب، QR، تمدید، توقف/ادامه، استقلال/rollback پروفایل، XSS و موبایل FA/EN را پوشش می‌دهد. این شاهد محلی است، نه گواهی تولید/اپراتور/ظرفیت Free. [نتایج، دستورها و hashها](docs/MESH_VERIFICATION.md).

## تصمیم‌های طراحی

۱. دو خروجی خودکفا با boot مستقل، نه fork رابط بالادستی یا ابهام نصبِ تغییر ROLE.
۲. دفتر معتبر D1 و نود بدون state؛ نه ضرب سهمیه در تعداد نود یا اجرای سقف با KV eventually-consistent.
۳. رزرو پیش از ارسال، ابهام صریح، مجوز زمان‌دار و شناسه ثابت عملیات؛ نه refund حدسی یا retry کور.
۴. راز مستقل مدیر/نود در محیط، نشست هش‌شده، Origin/CSRF؛ بدون دنبال‌کردن redirectِ دارای اعتبار، asset/کد بیرونی یا تله‌متری.
۵. حفظ ربات/دادهٔ قبلی و اصلاح WebSocket آن؛ بدون مهاجرت پنهان مالی، هویت یا URL به Mesh.
۶. فرض‌های نیازمند تأیید تولید: نود/ساعت مورد اعتماد، artifact فعال، TCP/کلاینت/اپراتور، پروفایل‌ها، پذیرش reconnect/رزرو، نگهداری داده و ظرفیت واقعی Cloudflare Free.

کد متعلق به NexiUP با MIT است؛ QR، MIT نایوکی و فونت دست‌نخوردهٔ Vazirmatn در مدیر، OFL-1.1 با متن کامل مجوز دارند. کد/رابط فایل پیوست، نهان یا edgetunnel وارد خروجی نشده است. [LICENSE](LICENSE) و [THIRD_PARTY.md](THIRD_PARTY.md)؛ مطابق شرایط Cloudflare و قانون استفاده کنید؛ **بدون ضمانت**.
